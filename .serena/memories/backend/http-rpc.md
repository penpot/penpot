# HTTP and RPC boundaries

- Start at `app.rpc/resolve-methods` for command discovery and `wrap` / `wrap-management` for request order. A new command namespace must be registered. `GET` and `HEAD` require a `get-` name; auth is on unless explicitly disabled. Metrics wraps concurrency, so RPC timing includes time spent waiting for a permit. Transaction handling sits inside the wrappers and is controlled by `::db/transaction`.
- A request `Origin` listed in `PENPOT_TRUSTED_ORIGINS` is stamped as `:app.http/trusted-origin` by `wrap-trusted-origin`, which binds `app.config/config` with `:public-uri` replaced by that origin for the request extent. Request-scoped links (emails, assets, audit/webhook fields, redirects) then use the alternate base; unlisted or absent origins and background work keep the canonical `:public-uri` (fail-closed). See `mem:backend/auth-sso` for the OIDC signed-state origin.
- Strip qualified client params before merging server auth context; only the server supplies the profile, auth type and token permissions. Malli map schemas are open by default. Keep public creation schemas closed to reject client IDs while allowing internal creation helpers to accept IDs for imports or duplication. See `wrap-params-validation` for JSON coercion and legacy spec fallback.
- A malformed body is a client error classified at the parse boundary, not by exception class. Preserve 400 `:malformed-json` for malformed input and 413 for oversized bodies. See `app.http.middleware` for parsing and `Accept`/`_fmt` response negotiation, and `mem:backend/metrics` for pre-dispatch counters.
- Upload schemas validate shape, not path ownership. Declare `::sm/params` as well as file keys in `::rpc/multipart-only-params`: the multipart guard runs inside `wrap-params-validation` and is skipped without a schema. Run `media.v/check-upload-path` before reading the file; see `mem:backend/media` for processing and storage. The binfile job creation RPC instead takes a chunked upload ID; see `mem:backend/binfile`.
- Session auth selects the cookie before the `Authorization` header. Only current `kid=1`/`ver=1` tokens enter the session decoder. The `:secure-session-cookies` flag controls the cookie's secure attribute; `app.config/parse-flags` adds `:disable-secure-session-cookies` for non-localhost HTTP. SameSite is `None` for CORS and otherwise follows `:strict-session-cookies`. See `mem:backend/session-expiration` for renewal and cleanup.
- Management shared-key authorization is outermost: a disallowed key must not validate params or open a transaction. `::rpc/allowed-shared-keys` omitted accepts any configured valid key; an empty set accepts none. See `mem:backend/permissions` for the product permission boundary.
