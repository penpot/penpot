# Backend binfile import and export

- Start at `app.binfile.common` for shared domain configuration, `app.binfile.jobs` for the job adapter, `app.rpc.commands.jobs` for the public envelope, and `app.binfile.v1`/`app.binfile.v3` for the formats. For cross-module model changes see `mem:common/data-model-change-checklist`; for durable execution see `mem:backend/jobs`.
- Keep legacy RPC and job configuration aligned on frozen IDs, team features and import size limits. The import creation request is not the stored job params: the server can determine the format from the upload, and audit uses manifest metadata, not file contents.
- Revalidate permissions when jobs run, not just when submitting: access can be revoked while queued. Import runs inside a transaction so an interruption cannot leave half a file. The job adapter stops on the heartbeat interrupt and checks again after the final tap; do not publish success if cancellation fell between the last tap and return. An upload not adopted by a job must be released; adopted import packages and temporary copies must be released on terminal outcomes.
- Keep the progress stage vocabulary shared across formats. Each tap carries its outer scopes, with no dependency on an earlier tap; throttling can drop intermediate events. Do not put source IDs or names into public progress. Normalize format-specific return shapes in the adapter rather than making the caller know the format.
- A v1 package can list a file twice (legacy export included libraries without deduping). Consume both objects of every entry to keep the stream aligned, but import and report the first occurrence only.
- v1/v3 import and v3 export's file read run inside long transactions. They extend the idle-in-transaction timeout without disabling it or extending the statement timeout; keep both limits distinct. See `app.binfile.common/transaction-idle-timeout-ms`.
- v1/v3 import links must refer to files in the package and reject self-links and dependency cycles, using the same check as the live link command. Keep iteration deterministic so the first edge wins consistently.
- The public export creation schema excludes `:public-uri`: the backend adds the effective full public base (including its path) as a string only after validating a trusted origin stamp. The worker uses that stored base for the download link without rechecking the allowlist; jobs with no such param use the worker's canonical base.
- Upgrade every `binfile` worker before enabling trusted aliases. The runner validates stored params before invoking the handler, and an older worker's closed export schema rejects the private `:public-uri` key as a permanent validation failure. To roll back, disable aliases on frontend and all backend instances, then keep upgraded workers running until queued export jobs with a saved base finish. Changing the allowlist never rewrites persisted params.
