# Backend media

- Start at `app.media/run`: ImageMagick and FontForge belong to the local path; `:remote-media-processing` sends supported operations through `app.media.remote`. Check the active flag before diagnosing a tool or output difference. The HTTP service contract lives in `mem:media-processor/core`; object lifecycle and buckets live in `mem:backend/storage`.
- Validate the upload path before MIME sniffing or size checks: those checks read the file. Keep unreadable paths distinct from files that exceed a size limit. For the outer multipart boundary see `mem:backend/http-rpc`.
- Keep SVG sanitization at final storage boundaries. Uploads, URL downloads, thumbnails and organization logos that store SVG use `app.media.svg/sanitize-svg-upload`; binfile imports use `app.binfile.common/sanitize-imported-svg`. Backend sanitization is a blocklist with namespace checks and escaped serialization. Check size before calling helpers that load the whole file; the upload limit does not bound the size of the sanitized output. Profile picture imports do not accept SVG.
- `app.media/download-image` checks status, declared length and MIME before writing a temp file, and checks the actual byte count afterward. This download path is separate from processing via the remote service.
- The per-team media byte quota is disabled on `upload-file-media-object` because summing storage objects on every upload was too costly. Do not restore the per-upload sum; keep the team lookup for audit attribution. The upload-session quota is separate.
