# Backend graph experiment

- Start at `app.graph.ingest` for cold projection, `app.graph.sync` for change application, `app.graph.schema.contract` for what gets projected, and `app.graph.debug` for session ownership and export. `app.http.debug` registers the routes; `backend/resources/app/templates/graph-console.tmpl` is the browser client.
- PostgreSQL file data remains authoritative. Cold projection and incremental sync must produce the same graph for the same file state; a Penpot shape-tree change can require updates to parent/frame columns, edges and ordered child lists together. Use `mem:common/changes-architecture` for change semantics. A new file attribute does not belong in the graph by default: decide it in the projection contract.
- Cold ingest writes graph provenance only after the base projection and derived transforms finish. Incremental sync consumes persisted file changes from file-topic Pub/Sub, not the console WebSocket. A browser reconnect refreshes the view but does not recover lost graph changes. The dropping buffer and revision gaps do not trigger replay; surface drift and reload from PostgreSQL. A failed batch can leave partial graph state; don't treat it as an atomic PostgreSQL transaction. Keep skipped changes and incomplete revisions visible.
- A session belongs to a profile, not a tab. Reload/replacement and unload own cleanup; do not assume TTL eviction. Sync, query and export use the same session lock: a long query blocks sync. Teardown closes the channel and resources, but does not take that lock; account for in-flight operations when changing the lifecycle. The Arrow allocator must outlive the Ladybug connection and database because Ladybug can retain staged Arrow buffers. Close the allocator last, including on failure.
- The console can read whole projected files and export their data. Keep routes behind both `:graph` and `/dbg` authorization, and preserve the engine's prepare/bind and read-only gate; text matching is not a substitute. Keep graph loading off the flag-disabled boot path. On a Ladybug or JVM upgrade, check graph-enabled startup, Arrow ingest, binder behavior and sync parity. Versions and JVM flags live in `backend/deps.edn` and the launch scripts.
- Verification entry points: `backend-tests.graph-sync-parity-test` compares incremental results to a fresh projection; `backend-tests.graph-binder-gate-test` prepares the actual statement templates. Neither replaces checking changes to session or route wiring. Use the focused backend commands with the assert flag in `mem:backend/testing`.
