# Penpot library

- `library/` exposes a JS builder for in-memory files and `.penpot` exports. Start at `library/src/lib/builder.cljs` for the JS boundary, `app.common.files.builder` for state changes, and `library/src/lib/export.cljs` for the archive. Usage is in `library/README.md`; commands are in `package.json`.
- The builder carries a current file, page and parent stack: add a file before a page and close nested boards or groups in order. Closing a group requires children and computes its geometry; a masked group uses its first child as the mask. `addBool` transforms an existing group rather than creating a separate object. See `app.common.files.builder` for the change records and compatibility feature defaults.
- Export writes ZIP entries sequentially, realizing delayed JSON or blob data as each entry is written. Preserve that ordering and laziness when changing progress or adding entries; `on-progress` follows each completed entry. The manifest carries the optional builder `referer`.
- Tests import `#self`, which resolves to `target/library/penpot.js`. From `library/`, rebuild with `pnpm run build:bundle` before `pnpm run test`, or the tests can run against a stale bundle. `library/scripts/test` performs both but also installs dependencies. The default `./scripts/ci library` checks do not build the bundle; see `mem:scripts/ci`.
- Changes to file construction in `common/` can affect this external builder even when the app still works. For cross-cutting test design see `mem:testing`; for migrations see `mem:common/file-migrations`.
