# Frontend errors and reports

- Start at `app.main.errors`, `app.main.repo/handle-response`, `app.main.ui.error-boundary` and `app.main.ui.static`. For report delivery outside the browser see `mem:audit-log`; for hands-on crash recovery see `mem:frontend/handling-crashes`.
- The store's `:exception` clears on `rt/navigated`, but React render errors live inside the boundary. Its reset keys are a real JS array of screen-name strings: the library uses JS array methods and `Object.is`, so a CLJS vector fails and rebuilt keyword objects reset unnecessarily. Reset on screen changes, not solely param changes; a crash on the same screen may need a reload.
- `app.main.repo/retryable-types` is the shared transient set. An unexpected transport response is not necessarily an app defect; repo classifies it before downstream handlers choose retry or notification. Keep environment failures on the audit-only path, not the internal defect reporter. Stale compiled chunks may need a throttled reload; plugin errors must stay isolated from the global exception page.
- Reserve the dedup slot before formatting. Keep the cache and payload bounded; a single error hint can embed a whole file and block a batch. Report names participate in dedup because external consumers distinguish handled errors from defects. Reset the governor between test cases that expect an emission.
- `flash` schedules reporting and the toast off the failing stack and resolves even if reporting fails; tests may await it. Do not reclassify a caller's report name just to select a compact display. For persistence use the underlying `:cause-type` to classify the wrapped error. Authentication and `vern` conflict delegate; `:not-found` is a terminal save failure that keeps the workspace open. The reload action on the save-failure report is a full restart, not a retry of the halted queue. See `mem:frontend/workspace-state-persistence-subtleties`.
