# Routing and app shell

- Start at `app.main.ui.routes`, `app.main.router` and `app.util.browser-history`. The token is `location.search`, not a store field; preserve the configured `public-uri` origin and subpath. The route table and legacy hash compatibility live in `app.main.ui.routes`.
- A shared frontend and backend use the same `PENPOT_TRUSTED_ORIGINS` list, serialized as data in `config.js`. `app.config` selects `location.origin` only on an exact match with a normalized entry: only scheme, host and port change, so the canonical path and trailing slash stay in `cf/public-uri`. With no match use the configured base; keep the browser-origin fallback when no public URI is configured. The reverse proxy must serve that same path on every alias.
- `X-Penpot-Origin` carries the page origin only on Penpot backend API paths that opt in to public base selection (RPC, including GET and multipart, and OIDC initiation). Do not add it to `app.util.http` defaults: fonts, assets, exporter-only requests and external URLs do not use it. The backend validates it separately from CORS; see `mem:backend/http-rpc`.
- Configure IPv6 aliases as the browser serializes the origin (e.g. `https://[::1]:9443`); expanded spellings do not match. After alias removal the frontend can reject the return URL while the backend still honors signed OIDC state: the user may need a new login on the canonical domain.
- Push of the current token does not write or notify; replace always writes and notifies, even for the same token, so URL corrections reach the router. `app.util.dom/replace-history-state!` intentionally rewrites without routing; do not substitute a notifying replace.
- Route data uses query params. A repeated param can decode as a vector; use `rt/get-query-param` for a scalar. Use `rt/token->query-string` at the SSO boundary: the server owns the destination origin. Use `rt/token->url` for a client-side absolute URL; do not require `screen`, since root flows can carry params such as a template without a route name. See `mem:backend/auth-sso`.
- `rt/nav-raw` exits the router; tests observe its destination by dereferencing the event, not by looking for an app listener. Unknown or empty routes verify the profile and teams before redirecting so root and invitation flows do not race. See `mem:frontend/auth-events` for login and invitations.
- Use the team-scoped navigation helpers in `app.main.data.common` rather than building the route at the call site. Their private `resolve-team-id` chooses the valid explicit ID, then the initialized team, then the current route's team, then the profile default. The route precedes the default so the user's personal team does not replace the team on screen. An invalid team route fails explicitly rather than rendering a blank shell.
- For store exceptions, React boundaries and report limits/classification see `mem:frontend/error-reporting`. For the client reaction to lost membership and job events see `mem:frontend/websocket-notifications`.
