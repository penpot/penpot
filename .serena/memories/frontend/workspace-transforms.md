# Workspace transforms

- Start at `app.main.data.workspace.transforms`, `app.main.data.workspace.modifiers` and `app.main.streams`. High-frequency WASM modifier and selection-rectangle previews use behavior subjects and refs outside normal store commits; they are not persisted shape data.
- Clear `wasm-modifiers` and `workspace-selrect` on gesture end **and** when a control unmounts mid-gesture. Otherwise stale preview state can displace the next selection overlay. `app.main.streams/clear-transform-preview!` resets both.
- A normal `mse/drag-stopper` can end a drag on `:interrupt` as well as mouse release. On save failure, `::plk/cancel-gestures` arrives first; `plk/gesture-stopper` marks the gesture cancelled so it clears the transform or drawing preview instead of committing. New drag gestures need that cancellation or equivalent unmount/read-only cleanup: the commit gate alone does not clear WASM preview state. See `mem:frontend/workspace-persistence`.
- `apply-modifiers*` updates frame guides and comment threads before `update-shapes`, with `:reg-objects? true` and `transform-attrs` limiting the diff. `assoc-position-data` preserves the original text shape context when applying derived text positions. Keep the `:position-data` tag on derived commits so its watcher does not react to itself.
- `calculate-ignore-tree` and its WASM counterpart compare each copy and its root before and after transforms. Small relative movement with effectively unchanged size and rotation can suppress geometry touched for descendants; resizes and rotations must still propagate it. For touched semantics and geometric precision see `mem:common/components` and `mem:common/geometry`.
- WASM modifier updates write local/plugin props rather than directly mutating file data. Rotation has distinct WASM and non-WASM event paths; check both when changing semantics. Rendering flush and tile invalidation are in `mem:render-wasm/rendering`.
