# Frontend CLJS unit tests

- Start in `frontend/test/frontend_tests/`; add new namespaces to `frontend_tests/runner.cljs`. From `frontend/`, use `pnpm run test:quiet -- --focus <namespace-or-var>` to compile and run a narrow test; the compiled runner alone does not rebuild after edits.
- Reproduce async behavior in async tests. `^:async` needs map-style fixtures, and promises from async helpers, fixtures and nested mock scopes must be awaited. Legacy `t/async` terminates through `done`, not the body promise. Missing awaits can leave a passing test with no assertions.
- Prefer `mock/with-mocks*` with an awaited body; use scoped mutable stubs so mocks survive `await`. Dynamic bindings do not. Close mocks and subscriptions after the terminal continuation, not just after sending the first event. Use `frontend-tests.helpers.async` and `frontend-tests.helpers.mock` for the available helpers.
- Subscribe before pushing to a hot stream. Use `await-response` for subscribe→push→await and observe terminal completion when asserting a sequence. When a state change can precede the last RPC, wait for the RPC through the mock; otherwise an in-flight call may hit real HTTP after teardown. Use a signal for a state-dependent wait when available; use explicit settling for ordering that has no signal.
- Mutable mocks are shared with background flows. Filter unrelated traffic when counting calls or releasing a wait. For variadic vs fixed arity stubs, use the correct helper: compiled `:esm` invocation can bypass a replacement aimed at the wrong arity. Use an empty stream for “completes without a value”; use a quiet subject for “stays open”.
- Treat `:fn-arity` as a defect: a compiled single-arity or variadic function can receive `undefined` rather than fail loudly. Incremental compilation only prints warnings when it rebuilds a namespace; see `mem:frontend/compile-diagnostics`.
- For `:infer-warning` in JS interop inside `set!`, hint the bound target symbol, not an inline expression. Put the return hint on the helper name when the helper returns a JS object and multiple callers need it.
- Non-obvious runtime boundaries: the `:esm` test target cannot load the CommonJS parser behind `tubax`; mock both SVG validation and conversion. For hook-order regressions, capture `console.error` as well as boundary callbacks; test the render direction where hooks are added (`frontend-tests.ui.team-container-test`). Scope suppression of expected noisy errors to the test.
- Coverage is over loaded namespaces; `unloaded.txt` is reported separately. Prefer line coverage to generated-JS branch percentages. The converter must read source text to handle CLJS source-map ranges; do not pass `ignoreSourceCode`. See `frontend/scripts/coverage.js` and `mem:scripts/coverage-reporting`.
