# Local CI (`scripts/ci`)

- From the repo root, use `./scripts/ci MODULE...` for the selected modules' lint, tests and format check. Build is opt-in. Run `./scripts/ci --help` for flags, modules and commands; `--dry-run` previews them without executing. For test design and output discipline, read `mem:testing`.
- Pass every changed module. A `common` change can affect frontend, backend, exporter and library; select affected consumers too. Backend lint includes common sources but its format task does not check common, so include `common` explicitly.
- The script appends `enable-backend-asserts` to `PENPOT_FLAGS`. Backend assertions are selected when code loads; running tests without the flag can compile them out. See `mem:backend/testing`.
- The default library test runs the existing bundle, unlike GitHub CI, which rebuilds first. Rebuild before relying on the result; see `mem:library/core`. `--fix library` currently calls the nonexistent `fmt:clj` script: from `library/` use `pnpm run fmt` instead until the orchestrator is corrected.
- `--build` uses module build commands but does not run by default or package deployable bundles. It avoids some cache-clearing wrappers; consult the command in `scripts/ci` rather than assuming every module's build has identical behavior. Native WASM build scripts serialize through a lock, but manual Cargo commands do not; see `mem:render-wasm/core`.
- `mcp` and `media-processor` have no lint task and are reported as skipped. The exporter test task supplies a fallback test secret when absent. `scripts/test_ci.py` tests orchestrator wiring and dry runs, not the module builds themselves.
- Full task logs are in `.ci-logs/<module>-<task>.log`; inspect them after failure and do not pipe test output directly to filters. `--dry-run` executes no tasks. For long full-module runs allow ample time. The `local-ci` skill is the verification entry point.
