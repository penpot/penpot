# Common change application

- Start at `app.common.files.changes` and the shape-tree helpers. `process-changes` validates the change vector once by default, reduces it and then processes collected touched changes; `verify? false` is for callers that already validated. A touched shape in a main instance can mark its component modified in the second pass.
- `:set` delegates to `ctn/set-shape-attr`; `:assign` decodes attrs before applying per-attr sets. `:position-data` is derived and never touched. Geometry and content-path comparisons use approximate equality for touched purposes, but width and height are excluded from the `is-geometry?` branch.
- `:mov-objects` and `:reorder-children` protect children inside component copies unless `allow-altering-copies` is set by a sync or swap flow. New structural change types must preserve that boundary.
- `cls/generate-delete-shapes` propagates deletion from inside a component main to referencing copies transitively across the file, preventing dangling `shape-ref`s. It skips this when deleting the main root itself or when `allow-altering-copies` is set.
- `shape-tree/add-shape` falls back invalid parents or frames to root, keeps parent `:shapes` a vector without duplicate IDs, and clears a copy parent's `:remote-synced` unless `ignore-touched`. `delete-shape` removes descendants from the objects map as well as unlinking the parent; render-wasm deletion has different undo internals.
- Page-object maps can carry metadata indexes. Rebuild them with `start-page-index` / `update-page-index` as appropriate; frontend commit application calls `ctst/update-object-indices` after page changes. For change construction and undo see `mem:common/changes-architecture`; for validation and repair see `mem:common/file-validation`.
