# Media processor

- Start in `media-processor/src/index.ts` for middleware order, `src/config.ts` for environment settings, and `package.json` for commands. The backend chooses local or remote processing; see `mem:backend/media`.
- Keep the service internal. Image and font routes require a matching `x-shared-key` before entering the queue; missing key configuration rejects processing requests but does not gate the health endpoint. The explicit service key overrides derivation from `PENPOT_SECRET_KEY`; keep it aligned with the backend. The backend connects via `PENPOT_MEDIA_PROCESSING_SERVICE_URI`.
- `src/upload-storage.ts` chooses memory or disk from the request's `Content-Length`, not from the final file size. Unknown length or a request at or above the threshold goes to disk. This threshold selects storage; it does not replace the upload size limit. Keep disk-upload cleanup on response finish and close, and conversion temp directory cleanup in `finally`.
- The request timeout starts before queue admission. A timeout or disconnect signals cancellation, but sending an HTTP response does not mean the work stopped. Sharp's native thumbnail operation cannot be cancelled through `AbortSignal`: hold the queue slot until it settles, then check cancellation. Keep the error middleware's release path for failures before a route handler takes over.
- In `src/services/image.ts`, validate source dimensions from metadata with the EXIF orientation accounted for, then check requested output dimensions before resizing. Keep Sharp's cache disabled to bound retained memory. Font subprocess limits and format handling live in `src/services/font.ts`; Linux uses `prlimit` for address-space and CPU limits.
- For local tests and formatting see `mem:scripts/ci`; for test design see `mem:testing`.
